# Step 09: Admin

Goal: the instance admin runs the instance from the web (`features.md`: instance admin, admin API, V1): accounts, organizations (quotas, suspension), storages and the default one, instance-wide login providers, settings, jobs. Everything `/api/v1/admin/*` offers; the usage dashboard stays later (`features.md`).

## `core` first: one gap

**The admin can't change an organization's owner.** Only the owner gives it away (`POST /organizations/{id}/owner`). An owner who left, lost their account or gave it to the wrong person (it happened while testing step 08) leaves the organization without a working owner, and the admin's only way out is deleting it; deleting that owner's account is refused while they own it. Added: `owner` in `PATCH /admin/organizations/{id}` (a joined member's email). A `core` minor release, pinned here.

## Where

- **`/admin`**, from the account menu ("Administration", instance admins only: `Me.instance_admin`); anyone else gets the 404 page. **Sub-pages**, not one page: the lists are long (up to 200 accounts or organizations each), unlike the account's or an organization's sections. A row of links under the title: Accounts, Organizations, Storages, Login providers, Settings, Jobs. `/admin` opens Accounts.
- The admin's own pages stay theirs: an admin is also an account and an owner, with the same pages as anyone.

## The pages

1. **Accounts** (`/admin/accounts`): a search (by email, the API's `q`), then each account: email, created, verified, admin, suspended. **Make admin / remove admin**, **suspend / lift**, in place (the server refuses leaving the instance without an active admin: said). **Delete** (GDPR erasure: someone else's data): confirmed by typing the email, shown to copy, as an organization's deletion; refused while it owns a company organization (said, with the organizations' names: give them another owner first). No account creation: accounts come from invitations and registration (decisions.md).
2. **Organizations** (`/admin/organizations`): a search, then each one: name, owner, members, usage of its quota (the bar from step 08), suspended, personal marked. **Edit** (a dialog): name (company only), quota (GiB, empty: none), suspended, default storage, **owner** (a joined member). **Create**: a name and its owner's email (an existing account). **Delete**: its name typed, as the owner's.
3. **Storages** (`/admin/storages`): each one: name, kind, chunks, used, the default marked; **Make default**. **Add**: the setup wizard's storage fields (filesystem path, or S3: endpoint, region, bucket, the key files, path style), moved into a shared component; the server tests it first (write, read back, delete), its refusal said. No editing or removing: the API has none (a storage holding chunks can't go).
4. **Login providers** (`/admin/providers`): the organization's section from step 08 reused, given the instance's endpoints; an instance provider takes its secret as a **file path** (the admin owns the server) or a value. Its logins open full sessions, and the login page lists it.
5. **Settings** (`/admin/settings`): every setting from `GET /admin/settings` (key, description, value, default), each shown by a **matcher**: a hand-made control for known keys and shapes, **the raw value for an unknown key** (a setting added to `core` shows up before the web app knows it). Matched by exact key or by shape, so a new key of a known shape gets its control too:
    - **Choices**: `registration` (open, closed), `organization_creation` (anyone, admins), `smtp_tls` (STARTTLS, TLS, none), `password_strength` (0 to 4, named as the strength bar names them).
    - **Switches**: `oidc_link_by_email`, `oidc_allow_internal_issuers` (`true`/`false`).
    - **Durations**, `*_secs`: a number and a unit (seconds, minutes, hours, days), stored in seconds; `session_max_lifetime_secs` at 0 says "no limit".
    - **Rate limits**, `rate_limit_*` (`count/seconds`): "N per" a duration.
    - **Numbers**: `max_pending_uploads`, `smtp_port`. **Text**: `instance_name`, `smtp_host`, `smtp_username`, `smtp_from`, `smtp_password_file` (a path, never the password).

    Each with its description, its default shown, **Reset** to the default (`null`). One **Save** sends the changed ones (`PATCH`, all or none: the server's refusal names the setting, said by its field). Grouped: general, sign-up and login, SMTP, rate limits, jobs (by key), unknown keys last.
6. **Jobs** (`/admin/jobs`): each job, its last runs (started, duration, status, items, error), **Run now** (then its new run shows, `running`, refreshed until it ends).

## Tests

Playwright, as the dev admin (an admin account), against the real server: an account suspended (its login refused), lifted, made admin and back; an account owning an organization refused deletion, then deleted once the owner changed; an organization created for an account, its quota set (its page shows it), its owner changed by the admin, deleted; a filesystem storage added (the server's container path) and made default, then the default restored; a setting changed (the registration closed: the login page's link gone), reset; a job run (its run listed). A non-admin gets no menu entry and a 404 on `/admin`.
